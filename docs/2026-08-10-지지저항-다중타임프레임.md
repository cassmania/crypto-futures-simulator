# 2026-08-10 다중 타임프레임 지지·저항 패널 이식

coin-ta-brief 스킬의 레벨 선정 방법론을 시뮬레이터 엔진으로 옮겼다.

## 왜 했나

2026-08-08 커밋 `10be5b8`가 프로젝트 패널의 지지·저항을 하드코딩에서 실시간
매물대 계산으로 바꿨다. 그건 맞는 방향이었지만 **현재 차트의 봉 하나**만 봤다.

스킬 방법론의 핵심은 그게 아니다. "여러 시간봉이 겹치는 레벨일수록 강하다"가
강도 판정의 1순위이고, 겹침을 세려면 봉을 여러 개 동시에 봐야 한다.
1h에서만 보이는 벽과 1h+4h+12h+1d 네 봉이 전부 가리키는 벽은 두께가 다르다.

## 뭘 넣었나

새 파일 `level_analyzer.js` (엔진, 브라우저/node 양쪽). 기존
`계산매물대구간()` / `실시간지지저항문구()` 는 **건드리지 않았다** —
프로젝트 패널 한 줄 요약은 그대로 쓰고, 새 패널이 정밀 분석을 맡는다.

### 레벨 후보 (스킬 3절 우선순위 그대로)

| 근거 | 가중 | 비고 |
|---|---|---|
| POC | 3.0 | 최대 거래 가격대 = 가장 두꺼운 벽 |
| 마지노선 | 2.8 | 200봉 극값. 이탈 시 지지 공백 |
| VA 경계 | 2.0 | 거래량 70% 구간 |
| HVN | 1.6 | 고밀도 매물대 |
| 스윙 고저 | 1.2 | 좌우 2봉 이기는 로컬 극값 |
| 피보 | 0.8 | 단독으로 약함. 겹칠 때 의미 |

타임프레임 가중은 1h 1.0 → 4h 1.3 → 12h 1.7 → 1d 2.0. 상위 봉 벽이 두껍다.

### 겹침 판정

가격 0.22% 이내 후보를 한 벽으로 묶는다(`MERGE_TOL`). 앵커는 가중 평균으로
계속 보정한다. 점수 = Σ(근거가중 × 봉가중), 강도 등급은 **서로 다른 봉 개수**로
매긴다 — 4중 겹침이 최강, 3중 강, 2중 중.

같은 봉에서 같은 종류가 여러 번 나와도 점수만 오르고 겹침 수는 안 오른다.
한 봉 안의 중복을 겹침으로 세면 단일봉이 4중으로 둔갑한다.

### 지지/저항 분리

현재가 기준으로만 가른다. **이탈한 지지는 저항으로, 돌파한 저항은 지지로**
자동 전환된다 — 근거 라벨은 출처를 남기므로 지지 목록에 "스윙고점"이 뜨는 건
버그가 아니라 전환된 벽이라는 뜻이다.

현재가 ±0.08%(`NEAR_GUARD`) 안쪽 후보는 벽으로 안 친다. 현재가에 달라붙은
노이즈가 "직상 저항 +0.01%"로 잡히면 쓸모가 없다.

## UI

`index.html` / `analysis.html` 양쪽에 `quant-levels` 탭 추가.
**두 페이지 다 손대야 한다** — 과거에 analysis.html만 고치고 완료 보고한 전례 있음.

패널 구성: 요약 → 직상/직하/마지노선/계산봉 4박스 → 저항표 → 지지표 → 조건부 시나리오.
각 행은 `가격 (거리%) / 근거 / 강도뱃지`. 시나리오는 돌파·이탈 두 갈래만 낸다.

## 캔들 조달

차트가 쓰는 봉 하나로는 부족해서 `레벨캔들가져오기()`가 1h/4h/12h/1d를 각각
200개씩 따로 받는다. 선물 API 우선, 실패 시 현물 폴백(기존 차트 정책과 동일).

**5분 캐시 필수.** 이 함수는 `AI추천분석및업데이트()` 안에서 불리는데 그건
틱마다 돈다. 캐시 없으면 초당 4회씩 바이낸스를 때려 레이트리밋에 걸린다.
`진행중` 플래그로 중복 요청도 막는다.

## 안 한 것

- 펀딩·OI·오실레이터: 스킬은 이것도 보지만 기존 퀀트 탭에 이미 있다. 중복 안 만든다.
- 뉴스·언락 조사: WebSearch가 필요해 브라우저 단독으로 불가능. 스킬 쪽에 남긴다.
- 차트 위 레벨선 드로잉: 기존 `차트지지저항선드로잉()`이 이미 있다. 별건.
