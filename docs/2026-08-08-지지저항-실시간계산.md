## 🐛 발견한 문제

`프로젝트데이터베이스`(app.js)에 지지·저항이 **고정 문자열로 박혀** 있었다. 시세가 흐르면서 값이 어긋났다.

| 종목 | DB 지지선 | DB 저항선 | 실제가 (2026-08-08) |
|---|---|---|---|
| BTC | 67,500 | 74,000 | **64,873** |

**지지선이 현재가보다 위에 있는 모순 상태.** 지지선은 정의상 현재가 아래여야 한다.

미등록 코인 경로도 문제였다. `현재가 × 0.982` / `× 1.018`로 ±1.8% 고정 배율을 썼는데, 매물대와 아무 관계 없는 임의값이다.

## ✅ 변경 내용

### 1. `계산매물대구간(candles, bins)` 신규

- **POC**: 최대 거래량 가격대
- **Value Area**: POC 기준 양옆으로 넓혀가며 거래량 70% 채우는 구간 (VAL~VAH)
- **마지노선**: 전 구간 최저 (이탈 시 지지 공백)
- **구간최고**: 전 구간 최고
- 실패 시 `null` 반환

### 2. `실시간지지저항문구(coin, candles)` 신규

후보(POC/VAL/VAH/마지노선/구간최고)를 현재가 기준으로 위아래로 갈라 **가까운 벽**을 고른다.

**이탈한 지지는 저항으로, 돌파한 저항은 지지로 전환** — 스킬 규칙 그대로다.

- 현재가가 구간최고 위 → `"구간 최고 돌파 (저항 공백)"`
- 현재가가 마지노선 아래 → `"마지노선 이탈 (지지 공백)"`

### 3. 렌더 지점 교체

```js
const 실시간레벨 = 실시간지지저항문구(coin, coin.캔들데이터);
document.getElementById("project-levels").innerText = 실시간레벨 || pInfo.지지저항;
```

계산이 실패할 때만 DB 값으로 폴백한다.

### 4. 미등록 코인 폴백 개선

±1.8% 임의 배율 → 실제 캔들 극값(`Math.max(high)` / `Math.min(low)`)
